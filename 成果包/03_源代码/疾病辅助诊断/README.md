# 猪病辅助诊断系统

面向「AI+农业」算法主题赛的作品原型。用文献知识库 + 症状加权匹配做**可解释**的猪病鉴别诊断，
并配一层独立的用药安全约束。

**⚠️ 定位声明**：本系统是学习研究用途的辅助工具，不能替代执业兽医的现场检查与诊断，
不可作为用药依据。

---

## 一、为什么这样做（而不是训练一个模型）

本项目**没有标注病例数据**，因此不存在「症状 → 确诊疾病」的监督训练集。
但疾病诊断本质上就是**鉴别诊断**——临床医生用的就是「症状 → 候选疾病」的对照推理。

所以本系统采用 **知识驱动 + 加权匹配**，而不是数据驱动的分类器。这不是降级，它带来三个关键性质：

| 性质 | 为什么重要 |
|---|---|
| **可解释** | 能说清"为什么怀疑是某个病"——命中了哪些症状、证据强度多高、缺了哪些 |
| **可审计** | 每条症状都带原文出处（文献编号 + 期刊年份 + 原句），可回溯核对 |
| **无需训练数据** | 直接绕开本项目最大的资源约束 |

```
pigdisease/
├── data/
│   ├── diseases.json               # 疾病知识库（构建产物，含每条症状的证据与出处）
│   ├── disease_dict.json           # 疾病词表（29 种病 / 76 个别名）—— 可手工扩充

├── kb_builder.py                   # 知识库构建：文献 → diseases.json

├── safety.py                       # 安全约束层：禁用拦截 / 休药期提示 / 证据不足降级

├── web/app.py                      # 网页演示界面（纯标准库，无需 Flask）
```

环境要求：**Python 3.8+，零第三方依赖**（全部用标准库）。

```bash
cd E:\harness\aic\pigdisease

python cli.py --list                            # 看知识库有哪些疾病

```

**可选**：启用大模型辅助口语归一化（默认关闭，纯规则即可运行）

```bash
set PIGDISEASE_LLM=1
set OPENAI_API_KEY=你的key
set OPENAI_BASE_URL=https://api.openai.com/v1
python cli.py "猪拉得跟水一样，还不吃料"
```

（`nlu.py` 做了白名单过滤）。否则不可控的概念会污染诊断链路。

## 四、知识库构建中的两个关键坑（这是本项目最重要的技术发现）

调参之前先修了这两个 bug，指标才有意义。**如果重建知识库，务必先确认这两点没被破坏。**

### 坑 1：PDF 抽取在中文字符间插入空格

抽取出的文本是这样：`黄 疸`、`紫 斑`、`眼 睑 水 肿`、`大 便 为 黄 绿 色`。

症状匹配是子串匹配，所以**凡是跨了空格的症状词全部匹配不到**。
后果：知识库只识别出 16 种病、130 条关联，"非洲猪瘟"只有 1 个症状。

修复：`kb_builder.normalize_cjk()` 反复压缩中文字符间的空白直到收敛。

**修复效果**：疾病 16 → 22 种，症状关联 130 → 259 条。
（注：这是压缩空格后的中间数字。随后改用句子级邻近抽取，交叉病污染被过滤，
最终定型为 **21 种疾病、211 条症状关联**，见下一节。）

### 坑 2：段落级共现导致跨病污染

兽医文献常见"多病综述"（一篇讲 5-10 种病）。用「症状词与病名同段即关联」的判据时，
一个段落里提到的所有病都会被挂上同段的所有症状。

实测副猪嗜血杆菌病被错误挂上 `腹泻 / 流产 / 神经症状`（它实际是多发性浆膜炎，
不该有这些症状），并在评测中造成大量误报。

修复：改用**句子级邻近**为主判据。

| 证据来源 | 判据 | 可信度 |
|---|---|---|
| 专论文献 | 题名含病名 → 全文症状计入 | 最高 |
| 句子邻近 | 症状与病名同句，或相距 ≤2 句 | 高 |
| 段落共现 | **仅当该段不涉及其他疾病时才计入** | 中 |

**修复效果**：Top-3 命中率 60% → **80%**，MRR 0.454 → **0.580**。

## 五、诊断算法

```
evidence(d) = Σ_命中症状  tier权重 × 症状特异性 × (0.6 + 0.4 × 文献一致度)
explain(d)  = 命中症状数 / 输入症状数            # 症状解释力
len_norm(d) = sqrt(4 / (4 + 该病症状表规模))      # 长度归一化，抑制广谱病名
score(d)    = (evidence × (0.7 + 0.3 × explain) + 日龄加分) × len_norm
```

四个设计要点：

- **tier权重**（强/中/弱 = 3/2/1）：证据强度分级
- **症状特异性** = 1 − 该症状在多少种疾病中出现。越独特越有鉴别价值，
  所以"腹泻"这种几乎人人都有的症状权重被自动压低
- **explain**：防止"只靠一个高频症状冲上第一"
- **len_norm**：知识库存在类别不平衡——症状表大的病对任何输入都能命中。
  用次线性抑制压制它，否则 24 个症状的病会霸占所有 Top-3 名额

### 证据分级规则

| 等级 | 判定条件 |
|---|---|
| 强 | 本病专论文献有记载，且 ≥2 篇独立文献支持 |
| 中 | 本病专论文献有记载（仅 1 篇），或 ≥2 篇文献支持且症状较特异 |
| 弱 | 其余（多为仅单篇非专论文献记载，疑似跨病污染） |

### 参数是怎么定的（不靠猜）

`python tune_tiers.py` 在固定评测集上扫描 7 组 tier 权重：

| 配置 | Top-1 | Top-3 | MRR |
|---|---|---|---|
| **强3/中2/弱1.0** | **40.0%** | **80.0%** | **0.580** |
| 强3/中2/弱1.5 | 40.0% | 73.3% | 0.572 |
| 强3/中2/弱2.0 | 40.0% | 73.3% | 0.589 |
| 强4/中2/弱1.0 | 40.0% | 73.3% | 0.563 |
| 强3/中2/弱0.5 | 40.0% | 73.3% | 0.556 |

也对比过用 `min-tier` **硬过滤**低置信症状：

| 策略 | 疾病数 | Top-3 |
|---|---|---|
| 全量保留（弱证据降权由 tier 权重处理） | 21 | **80.0%** |
| 只保留「中」及以上 | 11 | 40.0% |
| 只保留「强」 | 4 | 26.7% |

**结论：硬过滤会删掉整类疾病，反而更差。全部保留 + tier 加权才是正解。**

## 六、安全层（独立于 AI 推理）

**核心设计原则：用药安全不能依赖概率模型的"自觉"。**
无论上游诊断给出什么，用药相关内容必须经本层校验才允许呈现。

| 规则 | 内容 |
|---|---|
| **R0** | 扫描**用户原始输入**中的禁用药物。养殖户常直接说"我用了氯霉素"，这种情况必须立刻阻断 |
| **R1** | 禁用药物拦截：命中清单 → 标红阻断并说明禁用原因与适用范围 |
| **R2** | 任何具体药物建议必须附带休药期核对要求，并声明"不是处方" |
| **R3** | 诊断证据不足 → 降级为"仅提示疾病方向"，**不输出任何用药建议** |

> R0 是实测发现漏检后补上的：最初只检查知识库的药物线索，用户输入里的
> "我用了氯霉素"会被完全漏掉。

`banned_drugs.json` 目前是**开发用简化版**，正式使用前必须用农业农村部最新公告逐条核对
（本地文献库编号 26 的《兽药管理条例》即为此用途）。

## 八、已知局限（必须如实说明）

1. **知识库是机器抽取的，未经兽医专家核对**。已验证的两个抽取 bug 已修复，
   但词表覆盖与分级规则仍可能有错。
2. **12 种疾病没有专论文献**，其症状全部是「中/弱」证据。这是 Top-1 只有 40% 的主因。
3. **非洲猪瘟只有 1 个症状**——因为它唯一那篇文献（编号 17）是"防控措施调研"，
   全篇没有症状描述。属文献本身缺陷，需补文献而非改代码。
4. **只有 15 条评测案例**，规模小且由开发者构造，存在主观性。
5. **口语归一化依赖词表**（74 个标准症状 / 298 个匹配词），词表外的说法会漏识别。
6. **禁用药物清单是简化版**，需按最新法规更新。
7. **本系统未做任何临床验证**，绝不可用于实际生产决策。
