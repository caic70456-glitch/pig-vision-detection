## 二、猪只检测器是怎么来的（这一段很关键）

### 先说一个踩到的坑

HuggingFace 上有仓库 `marcosvmf/yolov8-piglife-sam3` 声称提供论文级猪只检测权重
（arXiv:2605.25860）。**但它上传的三个文件全是 COCO 预训练模型**，不是猪检测器：

| 文件 | 实测 `head.nc` | `train_args.data` | 结论 |
|---|---|---|---|
| yolov8n-pig.pt | 80 | coco.yaml | 与官方 `yolov8n.pt` **SHA256 完全一致** |
| yolov8s-pig.pt | 80 | coco.yaml | COCO 模型改名 |
| yolov8m-pig.pt | 80 | coco.yaml | COCO 模型改名 |

**教训：拿到第三方权重必须验证 `head.nc` 与 `train_args.data`，不能只看文件名和 README。**

### 于是自己训练

数据用 **PigBench**（`jonaden/pig-detection-and-tracking`，CC-BY-4.0）：
- 论文：Benchmarking pig detection and tracking under diverse and challenging conditions,
  *Computers and Electronics in Agriculture*, 2025, doi:10.1016/j.compag.2025.111264
- 单类 `pig` 标注；本机抽取 500 张训练 / 80 张测试
- 测试集 80 图共 1,730 个猪框，每图平均 14.2 头，含 10.7% 小目标（面积<1%）

训练配置：YOLOv8n（COCO 骨干迁移，`nc` 从 80 改为 1）、640px、batch 8、15 epochs、
SGD lr0=0.005、CPU（i9-13900H，14 线程）、约 40 分钟。

```bash
python extract_subset.py --split dev --limit 500     # 取训练集
python train_pig_detector.py --epochs 15 --batch 8   # 训练
python export_onnx.py                                # 导出 ONNX
```

### 训练曲线与最终指标

| epoch | mAP50 | mAP50-95 | Precision | Recall |
|---|---|---|---|---|
| 1 | 0.8320 | 0.5393 | 0.8309 | 0.7561 |
| 5 | 0.9181 | 0.6296 | 0.9334 | 0.8220 |
| 10 | 0.9390 | 0.6696 | 0.9490 | 0.8595 |
| **15** | **0.9395** | **0.6724** | **0.9551** | **0.8607** |

**测试集最终指标：mAP50 = 0.9396，mAP50-95 = 0.6725，Precision = 0.9545，Recall = 0.8602**
推理速度：**37 ms/张**（CPU）。

对比效果（同一张真实图片 danuma_1262.jpg）：

| | COCO 假模型 | 自训猪检测器 |
|---|---|---|
| 类别 | 80 类 COCO | `{0: 'pig'}` |
| 检出数（真值 23） | 8 | **24** |
| 平均置信度 | 0.528 | **0.782** |

模型产物：
- `models/pig-detector-yolov8n.pt`（5.94 MB，ultralytics 直用）
- `models/pig-detector-yolov8n.onnx`（12.27 MB，脱离 ultralytics 部署）

## 五、行为识别规则（可解释、可审核）

| 行为 | 判据 | 证据类型 |
|---|---|---|
| 采食 eating | 与食槽区域重叠 ≥ 0.35 | 设施锚定（空间） |
| 饮水 drinking | 与饮水器区域重叠 ≥ 0.35 | 设施锚定（空间） |
| 争斗 aggressive | 与相邻个体 IoU ≥ 0.12 且双方有位移 | 时空联合 |
| 行走 walking | 每帧位移 ≥ 0.012 或窗口累计位移 ≥ 0.05 | 时序 |
| 休息 resting | 框面积相对缩小 ≥ 15% | 姿态（时序） |
| 站立 standing | 位移极小且面积无明显变化 | 时序 |

**规则优先级经过实测修正**（开发中踩到的三个真坑）：

1. **设施锚定行为必须优先于「框重叠」判据。**
   最初把「争斗」排在「采食」之前，导致「4 头同槽采食」因框相邻重叠被**全部误判为争斗**。
2. **姿态变化（面积）必须优先于运动判据。**
   猪从站到卧时面积明显缩小但位移很小，若先判运动会被误判为「站立」。
3. **跨帧配对必须逐帧、面积变化取首末总差。**
   最初按步长跳帧配对只覆盖前半段，「末期卧倒」被漏掉；面积变化取各帧均值会前后抵消。

每个判定都输出触发的规则名、特征值与阈值（CLI 输出的「依据」列），
阈值集中配置在 `behavior.py` 的 `TH` 字典，便于按现场重新标定。

## 六、设施区域标定（当前最该做的一步）

### 为什么必须标定

设施区域是「采食」「饮水」两个行为的**空间锚点**——系统靠「猪是否在食槽/饮水器区域内」
判断它在干什么。区域不对，这两个行为必然判错。

`scene.infer_regions()` 提供的**布局先验**（食槽左下、饮水器右下）只适用于固定机位的侧拍画面，
套在真实俯拍图上会严重误判。

### 标定效果实测（真实猪舍图片，152 个目标，同一检测结果只切换区域来源）

| 行为 | 布局先验推断 | 人工标定 | 变化 |
|---|---|---|---|
| 采食 | 7.9% | **32.2%** | **+24.3%** |
| 争斗 | 4.6% | **1.3%** | **−3.3%** |
| 饮水 | 13.2% | 9.2% | −4.0% |
| 站立 | 66.4% | 51.3% | −15.1% |

**采食占比提升 4 倍**，因为标定后的食槽区域真正覆盖了猪只采食的位置。
复现：`python compare_regions.py`

### 怎么标定

```bash
python annotate_regions.py 你的猪舍照片.jpg
```

界面操作：

| 操作 | 说明 |
|---|---|
| `1` / `2` / `3` / `4` | 切换要画的区域类型：食槽 / 饮水器 / 保温区 / 栏舍边界 |
| 鼠标左键拖拽 | 画出矩形 |
| 鼠标右键点击 | 删除该区域内的框 |
| `Ctrl+Z` | 撤销上一个框 |
| `Ctrl+S` | 保存　`Ctrl+O` 载入 |
| `R` | 重置全部 |
| `Esc` | 退出（未保存会提示） |

**标定要点**
- **食槽、饮水器是必需的**（界面上带 `*`），保温区和栏舍边界可选，只影响报告描述
- 同一类区域可画多个框（例如两侧各有一个食槽）
- **框要贴合设施实际占地，宁小勿大**——框太大会把栏中的猪也误判成在采食
- 保存为 `regions.json`，坐标为**归一化值（0~1）**，因此同一份配置
  可套用到不同分辨率的图片或视频帧，换相机分辨率也不会错位

**校验配置**（不启动界面）：

```bash
python annotate_regions.py --check regions.json
```

会检查必需区域是否齐全、坐标是否越界、食槽与饮水器是否重叠过多。

### 配置如何被使用

`pipeline` 自动查找图像同目录（或最多三级父目录）的 `regions.json` 并应用，无需手动指定。
也可显式指定：

```bash
python cli.py 照片.jpg --regions 我的配置.json
```

报告里会明确区分两种状态：
- `设施区域：已人工标定` → 空间锚点可靠
- `⚠ 设施区域：布局先验推断，未人工标定` → 提示「采食/饮水」可能误判

### 顺带修掉的一个真实误报

标定后发现「争斗」仍偏高，于是做了阈值扫描（`sweep_fight_threshold.py`，12 图 236 个目标）：

| fight_iou | 争斗占比 |
|---|---|
| 0.12 | 20.3% |
| 0.25 | 7.6% |
| **0.35** | **3.8%** |
| 0.60 | 0.8% |

猪群实际争斗通常 <5%，因此采用**双阈值**设计：

| 证据类型 | 阈值 | 原因 |
|---|---|---|
| 静态单帧 | 0.35（保守） | 只能靠重叠度，密集采食时相邻框必然重叠，很容易误报 |
| 视频时序 | 0.15（宽松） + 要求双方都有位移 | 有运动证据可验证，能更准地捕获真实争斗 |

**为什么必须双阈值**：真实争斗的 IoU（~0.17）与密集采食的误报 IoU（~0.15-0.32）
**分布本身是重叠的**，单一阈值无法分开。实测若用单阈值 0.35，时序评测会从 7/7 掉到 5/7。

## 八、已知局限（必须如实说明）

1. **行为评测是合成的**，不代表真实场景精度。已用真实图片验证的是「检测」与
   「标定影响」，行为分类本身的准确率仍待真实标注数据验证。
2. **跨帧跟踪是最简贪心匹配**（按中心点最近邻），未用 ByteTrack/DeepSORT。
   拍摄角度变化大或个体交叉时会跟丢。
3. **没有个体识别（ReID）**，只能做群体级行为分布，无法做「个体采食量下降」预警。
4. **视频处理依赖外部工具**抽帧（本机无 opencv）。
5. **健康评估基线未标定**，默认值是示例，程序已明确声明并禁止在单帧下给结论。
6. **训练数据仅 500 张**，覆盖猪舍场景类型有限；扩大到 2,682 张 dev 集可进一步提升。
7. **行为阈值按单个数据集标定**（`behavior.py` 的 `TH`），换猪舍或换相机场合需重新标定。
8. **LICENSE 注意**：PigBench 为 CC-BY-4.0（可商用需署名）；
   那个假权重仓库是 CC-BY-NC-4.0（非商用），本系统未使用其权重。

## 九、下一步（按重要性排序）

1. **标定你自己的猪舍区域**（`annotate_regions.py`）—— 拿手机拍几张照片，
   框选食槽与饮水器，这是让系统真正可用的第一步。
2. **采集真实猪舍视频并人工标注行为片段**，建立真实行为评测集
   （当前行为指标来自合成数据，不足以写进作品方案的「应用成效」）。
3. **扩大到全量训练集**（2,682 张 dev）并把 epochs 提到 50-100，
   预计 mAP50-95 可提升到 0.70+。
4. **引入 ByteTrack**（ultralytics 已内置 `tracker=botsort.yaml`）做更稳的跨帧关联。
5. **增加个体识别**，实现个体级行为时长统计。
6. **扩充行为类别**：发情行为、跛行、异常呼吸姿态。
